# 设置向导设计

状态:设计已确认(2026-11-24),待实现。2026-11-25 补充:证书一步可以跳过,先用 HTTP(见“已确认的决定”)。

## 背景和目标

现在部署 Ferry 要读 [deploy/README.md](../deploy/README.md),在服务器上手动填 `.env`、改 Traefik 配置、放证书、用命令行建管理员。
目标是:服务器上只运行一条安装命令,剩下的初始化工作都在浏览器里按向导完成。

向导做两类事:

- **引导**:DNS 解析和证书要在阿里云等外部服务上操作,由人完成。向导告诉人要做什么、怎么做,并检查做对了没有。
- **配置**:Ferry 自己的配置(域名、证书安装、第一个管理员、自检)由向导直接完成。

## 分工边界

**向导和安装命令都不操作任何外部服务**(阿里云的 DNS、RAM、证书服务等),也不保存外部服务的凭据。
所以不采用“Traefik 拿阿里云 AccessKey 自动申请、续期证书”的方式,证书由人申请后上传。

| 谁 | 做什么 |
|---|---|
| 人(外部操作) | 准备 Linux 服务器;在阿里云加两条 A 记录;在阿里云数字证书管理服务申请证书并下载 |
| 安装命令(服务器上,以后写) | 装 Docker 和固定版本的 Dokploy,用接口注册 Dokploy 管理员、生成 API key(见 [dokploy-findings.md](dokploy-findings.md));去掉 Traefik 默认的 letsencrypt、关掉管理接口;生成 `GATEWAY_SECRET`、`SECRETS_KEY`、数据库密码写进 `.env`;配置防火墙;启动 Ferry;打印向导地址和设置码 |
| 设置向导(浏览器) | 下面的 7 步 |

先做向导、后写安装命令:向导可以在本机(`pnpm dev` + 本机 Dokploy)开发测试,安装命令要 Linux 虚拟机。

## 流程

| 步 | 地址 | 内容 |
|---|---|---|
| 1. 设置码 | `https://服务器IP/setup` | 输入设置码。用 Traefik 自带的自签名证书,浏览器提示一次警告;这样从第一步起就是加密的 |
| 2. 域名和 DNS | 同上 | 填公司域名,向导给出要加的两条记录和阿里云的操作说明;人加好后点“检测” |
| 3. 证书 | 同上 | 说明要申请覆盖哪些域名的证书、怎么申请和下载;上传后检查并装进 Traefik。可以跳过,先用 HTTP |
| 4. 切到正式地址 | 跳到 `https://ferry.公司域名/setup` | 用正式证书;浏览器不再警告。跳过证书时不跳转,第 5 到 7 步留在 `https://服务器IP` |
| 5. 公司和管理员 | 正式地址 | 公司名(最上级部门)、第一个管理员的手机号、姓名、密码 |
| 6. 自检 | 正式地址 | 发布一个测试应用,检查能打开、未登录会跳转登录,然后删除 |
| 7. 完成 | 正式地址 | 提示备份服务器上的 `.env`(含 `SECRETS_KEY`);向导永久关闭,进入控制台 |

数据库定时备份(任务 3.4)还没做,向导暂时不含备份设置,做了之后再加一步。

### 2. 域名和 DNS

- 输入:公司域名(如 `example.com`),Ferry 子域名默认 `ferry`、应用子域名默认 `apps`,可改;服务器的内网 IP 自动探测,可改。
- 显示要加的记录:`ferry` → IP、`*.apps` → IP,类型 A;以及阿里云控制台的操作步骤和“DNS 重绑定保护”的说明。
- 检测(都在服务器上做):
  1. 解析 `ferry.example.com` 和一个随机名字 `ferry-check-<随机>.apps.example.com`,都应该得到本机 IP。
  2. 用这个域名经 Traefik 的 80 端口请求 Ferry 的 `/api/setup/ping?nonce=…`,返回同一个 nonce,证明解析到的就是这台服务器、Traefik 能转过来。
- 人自己的电脑:这一步还查不了。向导页面在 `https://IP` 上,不能请求 http 地址(浏览器拦截混合内容),
  正式证书也还没装,请求 https 会证书报错。所以只给出 `nslookup` 命令让人自己查,真正的检查放在第 4 步:能跳转到正式地址,就说明人的电脑能解析、能访问。
  第 4 步跳不过去时,页面列出可能的原因(还没生效、IP 不对、路由器拦截了内网地址、浏览器走了代理)。
- 通过后保存域名(还不生效,第 4 步才生效)。

### 3. 证书

- 说明:证书要覆盖 `ferry.example.com` 和 `*.apps.example.com`(一张多域名证书,或两张);阿里云免费证书不支持泛域名,要购买;
  下载“Nginx”格式,得到 `.pem`(证书链)和 `.key`(私钥)。
- 上传后在服务器上检查(Node 的 `crypto.X509Certificate`):
  - 证书链能解析;叶子证书的 SAN 覆盖上面两个域名;
  - 私钥和证书匹配;
  - 证书链完整(带中间证书),能用系统信任的根证书验证通过;
  - 剩余有效期,少于 30 天时警告。
- 安装:通过 Dokploy 的证书管理接口上传(Dokploy 自己把文件和 Traefik 的 TLS 配置写进它的目录)。Traefik 不会自己发现新证书,
  上传后用 `settings.updateTraefikFile` 把 Ferry 的 `ferry-gateway.yml` 原样重写一次触发重新加载,不用重启(见 [dokploy-findings.md](dokploy-findings.md))。
  Ferry 不直接写服务器上的文件。保存 Dokploy 返回的证书 ID、证书的到期时间和覆盖的域名,替换证书和到期提醒要用。
- 验证:从服务器用 `https://ferry.example.com/api/setup/ping` 实际握手一次,校验证书(不跳过校验)。
- **跳过**:“暂时不用 HTTPS”,确认后 Ferry 和所有应用先走 HTTP(`apps_url_scheme` 为 `http`,`public_url` 为 `http://ferry.example.com`)。
  确认框只说两点:密码和 agent 令牌会在内网明文传输;之后在控制台“证书”页上传即自动换成 HTTPS(见“证书:到期提醒、替换和补装”)。
  不用 Traefik 的自签名证书硬上 HTTPS:每个员工每次打开都会看到警告,agent 也会因证书不受信任连不上。

### 4. 切到正式地址

- 把第 2 步的域名写成生效的配置,Ferry **重启**一次(见“配置怎么生效”)。
- 重启期间和重启后,页面一直留在 `https://IP/setup` 上。第 7 步完成之前,服务器 IP 上的 `/setup` 一直可用(见“Ferry 自己的路由”),
  向导会话存在数据库里,重启后还有效。
- 页面在浏览器里检查正式地址能不能打开:`fetch("https://ferry.example.com/api/setup/ping", { mode: "no-cors" })`。
  这是跨域请求,不读返回内容,不需要 CORS 头;请求成功说明人的电脑能解析域名、连得上、证书可信,出错说明还不行。
- 可以打开后,页面向 `https://IP` 自己的 `/api/setup/handoff` 要一个一次性的交接令牌(同源,带向导会话),
  再跳到 `https://ferry.example.com/setup?handoff=…`,在正式地址上换成新的向导会话,不用再输一次设置码。
  交接令牌在这时才签发,只存哈希(在数据库里),5 分钟有效,只能用一次。
- **第 3 步跳过时**不交接,第 5 到 7 步留在 `https://IP` 上:交接令牌放在 http 地址里会明文传输,局域网里截到的人能抢先用掉、在第 5 步把自己建成管理员;
  留在 https 上,向导会话 cookie 照样是 Secure,管理员密码也是加密传输的。
  这时也没法在页面里检查 http 地址能不能打开(页面在 `https://IP` 上,浏览器会拦截发往 http 的 `fetch`,混合内容),
  所以重启后给出 `http://ferry.example.com` 的链接,人在新标签页里打开确认,点“能打开”再继续;打不开时页面列出常见原因。

### 5. 公司和管理员

和现在 `pnpm set-password <手机号> --name <姓名> --org <公司名>` 做的事一样:建最上级部门和第一个平台管理员。
区别是密码由人自己在页面上设置(不是生成初始密码再改),规则沿用现有的密码规则。

### 6. 自检

以一个内部的系统身份做一遍员工的发布流程:用 node-postgres 模板建应用 `ferry-selfcheck`、上传、发布、等待上线;
然后不带登录状态请求应用地址,应该跳转到 Ferry 登录页;最后彻底删除这个应用(含数据库)。
失败时显示是哪一步、错误信息和处理建议(多半是 Dokploy 或 Traefik 的问题)。允许跳过,跳过会记在审计日志里。

## 关键设计

### 未初始化模式

Ferry 启动时判断是否已初始化:

- **已初始化**:满足下面任一条:
  - 环境变量里设了 `PUBLIC_URL`(现有的部署方式)。看原始的 `process.env`,不看解析后的配置;`APPS_DOMAIN` 在 `config.ts` 里有默认值,不能用来判断。
  - 数据库里有“初始化完成”的记录。
  - 只在本机监听(`HOST` 是回环地址,本机开发的默认值),只有本机能访问,不需要向导。这样 `pnpm dev`、`pnpm test:dokploy` 和本机模拟试用照常。
    开发向导本身时设 `SETUP_DEV=1`,强制进入未初始化模式。
- **未初始化**:只开放 `/setup`、`/api/setup/*` 和 `/healthz`。登录、控制台、MCP、上传、登录网关 `/authz` 都返回“还没完成初始化”。

未初始化时不要求 `PUBLIC_URL`:现在“监听其他机器的连接就必须设 `PUBLIC_URL`”的启动检查,在未初始化时跳过。
初始化完成后 `/setup` 和 `/api/setup/*` 一律返回 404,不能重新进入向导(要重来只能清空数据库)。

### 配置存在哪里、以哪个为准

新增一张表 `instance_settings`(单行),保存向导写入的配置:

| 字段 | 说明 |
|---|---|
| `public_url` | 如 `https://ferry.example.com` |
| `apps_domain`、`apps_url_scheme` | 如 `apps.example.com`、`https` |
| `certificate` | Dokploy 证书 ID、到期时间、覆盖的域名 |
| `setup_code_hash`、`setup_completed_at` | 设置码的哈希;完成时间 |

向导会话和交接令牌也存数据库(只存哈希、带过期时间),第 4 步重启后仍然有效。

**环境变量优先**:环境变量里设置了的,用环境变量,向导里对应的项显示为“由服务器配置固定”。这样现有的部署(全靠 `.env`)完全不受影响。

不进数据库的:`SECRETS_KEY`(它用来加密数据库里的应用密钥,不能和密文放在一起)、`GATEWAY_SECRET`、`DOKPLOY_API_KEY`、
数据库密码。这些由安装命令生成,写在服务器的 `.env` 里。

### 配置怎么生效

`PUBLIC_URL` 等在启动时被很多地方用到(上传地址、允许的来源、cookie 的 Secure、登录网关的跳转地址、发给 agent 的控制台地址),
改成运行时可变的改动面太大。所以第 4 步保存后让 Ferry 退出,由 Docker 的 `restart: unless-stopped` 拉起,启动时读到新配置。
本机开发时 `tsx watch` 不会在进程退出后拉起,需要手动重启,向导页面上会提示。

### Ferry 自己的路由

现在 Ferry 的 Traefik 路由写在 compose 的标签里:`Host(${FERRY_HOST})`,容器创建时就定死了,向导改不了。改成:

- **兜底路由**:`PathPrefix(/)` 且不是 `/authz`,优先级最低。Traefik 一个 router 不能同时在 `web` 上走明文、在 `websecure` 上走 TLS
  (配了 `tls` 的 router 只匹配 TLS 连接),所以拆成两个,和现在的 `ferry`、`ferry-http` 一样:
  `websecure` 上一个,`tls: true`,没有匹配的证书时用 Traefik 默认的自签名证书;`web` 上一个,不带 tls。
  员工应用的路由都是具体的 `Host(...)`,优先级更高,不受影响;没有被任何应用认领的域名(包括服务器 IP)都到 Ferry。
- Ferry 自己按请求的域名分流:未初始化时(包括第 4 步重启后、第 7 步完成前)任何域名和 IP 都只认 `/setup`;初始化后,`PUBLIC_URL` 的域名照常服务,
  应用域名下的未知应用返回“应用不存在”,其他域名返回 404。
- http 跳 https 的中间件保留,但只在初始化完成**并且装了证书**之后,对 Ferry 自己的域名生效(第 2 步的 ping 要走 http;
  跳过证书时没有可用的证书,跳过去只会看到证书警告)。

已验证(2026-11-24,见 [dokploy-findings.md](dokploy-findings.md)):应用的 `Host(...)` 路由优先于兜底路由,没有应用的域名和服务器 IP 到兜底,`/authz` 不接;`https://IP` 用 Traefik 默认的自签名证书。

### 设置码

- 未初始化时 Ferry 第一次启动生成一个设置码(12 位,去掉易混字符),数据库里只保存哈希。
  明文不打进日志(日志保留 50m×10,和“生成的密码和 key 不打印到日志”一致),写进数据卷上的文件 `/data/state/setup-code`(`chmod 600`;compose 新增数据卷 `state:/data/state`,容器重建后还在),
  日志里只说“设置码已写入 /data/state/setup-code”。安装命令用 `docker compose exec ferry cat /data/state/setup-code` 读出来在终端显示一次;
  忘了时人也可以这样查。完成初始化后删除这个文件。
- 输对后发一个只用于向导的会话 cookie(HttpOnly、Secure、SameSite=Strict,2 小时)。向导的每一步都在 https 上
  (跳过证书时第 5 到 7 步留在 `https://IP`,见第 4 步),所以总能带 Secure。
- 连续输错 5 次锁定 10 分钟。重启 Ferry 不换设置码,完成初始化后作废。
- 向导的每个修改请求都检查会话和来源。向导会用服务器 IP 和正式域名两种地址打开,不能用按 `PUBLIC_URL` 算出的来源列表,
  改为要求 `Origin` 和请求的 `Host` 一致(同源)。
- 输错次数按来源 IP 分别计数(经 Traefik 时取它设置的 `X-Forwarded-For`,客户端伪造不了):只锁输错的来源,别人反复输错不会把管理员锁在外面。所有来源合计输错 50 次时全部锁 10 分钟,防止换着来源猜。计数在内存里,重启 Ferry 会清零(12 位设置码约 59 位随机,不影响安全)。

## 安全

| 风险 | 处理 |
|---|---|
| 内网里别人先打开向导,抢先设置 | 没有设置码什么都做不了;设置码只在服务器上的文件里,不进日志 |
| 向导期间传私钥、密码被抓包 | 向导每一步都是 https(先用 Traefik 自签名证书,第 4 步起用正式证书;跳过证书时一直留在 `https://IP` 的自签名证书上);管理员密码在第 5 步才设置 |
| 跳过证书后明文传输 | 人在第 3 步明确确认;向导本身不交接、不走 http;向导完成后的登录、令牌走 http,控制台顶部对管理员常驻“还没启用 HTTPS”提醒,直到装上证书 |
| 向导完成后被重新打开、篡改配置 | 完成后 `/setup` 永久 404;完成状态只能通过清空数据库重置 |
| 证书私钥泄露 | Ferry 不保存私钥,只交给 Dokploy;Ferry 只记证书 ID、到期时间和域名 |
| 向导操作外部服务 | 不做;没有任何外部服务的凭据 |
| 设置码被暴力猜测 | 12 位随机,输错 5 次锁 10 分钟 |

## 和现有部署的兼容

- `.env` 里已经有 `PUBLIC_URL` 和 `APPS_DOMAIN` 的部署,启动即为已初始化,向导不出现,行为和现在一样。
- compose 现在 `PUBLIC_URL` 和 `FERRY_HOST` 都是必填(`${…:?…}`)。不改的话,安装命令不写 `PUBLIC_URL` 时 compose 不启动;
  写了又会被判定为已初始化,向导不出现。所以要一起改:`PUBLIC_URL` 改成可选(`${PUBLIC_URL:-}`,空值按没设处理),
  路由从 `Host(${FERRY_HOST})` 改成兜底路由后 `FERRY_HOST` 不再需要。已部署的服务器 `.env` 里两个都有,升级时不用改。
  compose 里 `HOST: 0.0.0.0`,不会因为“本机监听”被当成已初始化。
- `set-password` 命令保留,用于忘记密码等情况。

## 一并要做的:证书到期提醒、替换和补装

证书不再自动续期(人工申请的证书,有效期按行业规定 2026 年起最长约 200 天),忘了换就所有应用同时打不开。

- Ferry 每天检查一次证书剩余天数,少于 30 天时在控制台顶部给管理员显示提醒,并写告警日志;少于 7 天每天都告警。
  还没有证书(向导第 3 步跳过了)时不检查到期,只显示“还没启用 HTTPS”。
- 管理员在控制台新增的“证书”页上传新证书,检查和安装逻辑和向导第 3 步相同。
- **补装**(向导第 3 步跳过了):还没装证书时,控制台顶部对管理员常驻“还没启用 HTTPS”提醒,链接到“证书”页。
  在那里上传并检查通过后:装进 Traefik,把 `public_url`、`apps_url_scheme` 改成 https,然后像第 4 步一样重启 Ferry。
  - 重启后打开 Ferry 自己域名的 http 跳 https,旧的 http 书签和应用链接都还能用。
  - 每个应用在 Dokploy 上的域名也要改成 https:启动时的域名检查(`ensureDomains` → `attachDomain`)现在只对齐端口、登录网关和路由文件,
    要一并对齐 `https` 和 `certificateType`。
  - agent 的 MCP 地址从 http 变成 https,要员工自己改:控制台“个人令牌”页显示新地址并提示一次。

## 不做的

- 自动申请、续期证书(需要外部服务的凭据)。
- 在向导里改防火墙(改错会把管理员挡在外面,留在安装命令里)。
- `AGENT_URL`、资源上限等高级配置(继续用 `.env`)。
- 重新进入向导。
