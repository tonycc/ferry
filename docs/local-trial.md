# 本机模拟试用

在企业环境就绪之前,在本机(Mac + 本机 Dokploy + `pnpm dev`)把 M2 小范围试用完整走一遍:
一个人扮演管理员和几名员工,用 Claude Code 当员工的 agent,只按员工能拿到的资料操作。目的是在真正试用前发现问题。

M2 的验收标准:**试用员工不经指导完成发布;同事登录后能访问;管理员能停用任意应用。**
“不经指导”指扮演员工时只做员工会做的事:用自然语言提需求、回答 agent 的确认问题。不看 Ferry 的代码和日志,不替 agent 改代码。

## 准备

- 本机 Dokploy 在运行(http://localhost:3000 能打开)。
- `pnpm dev` 在运行,并且 `.env` 里有 `FERRY_PLATFORM=dokploy`、`APPS_DOMAIN=apps.localhost`、`APPS_URL_SCHEME=http`、
  `ADMIN_USERS=dingtalk:admin`、`NOTIFY_VIA=log`、`SECRETS_KEY`。Ferry 地址是 http://127.0.0.1:8080 。
- 管理员能登录(没有密码时运行 `pnpm set-password 13800000005`)。
- 给负责人的通知、给管理员的告警都打印在 `pnpm dev` 的终端里,形如 `[通知 → dingtalk:dave] ...`、`[告警] ...`。

**每个人用一个单独的浏览器窗口**:登录 cookie 是按 Ferry 地址存的,同一个窗口只能登录一个人。
可以用不同的浏览器,或者 Chrome 的不同个人资料 / 无痕窗口。

**每个员工的 agent 用一个单独的空目录**,在那个目录里配 MCP,互不影响,也不改你平时用的 Claude Code 配置。
令牌页给出的命令是 `--scope user`(全局生效),模拟时改成 `--scope local`(只在这个目录生效):

```bash
mkdir -p ~/ferry-trial/dave && cd ~/ferry-trial/dave
claude mcp add --transport http --scope local ferry http://127.0.0.1:8080/mcp --header "Authorization: Bearer <Dave 的令牌>"
claude mcp list
```

## 角色

| 角色 | 用户 | 手机号 | 部门 | 用途 |
|---|---|---|---|---|
| 管理员 | Admin | 13800000005 | 信息部 | 生成初始密码、停用和恢复、看审计日志 |
| 员工 A | Dave | 13800000003 | 财务部 → 应付组 | 主要的发布者 |
| 员工 B | Bob | 13800000002 | 财务部 | Dave 的上级部门的同事;也发布一个全公司可见的页面 |
| 员工 C | Carol | 13800000004 | 销售部 | 别的部门的同事 |

Alice 的账号下有之前测试留下的几十个应用,模拟时不用她。

“本部门可见”的规则:和负责人同部门,或者在负责人部门的**上级**部门里。所以 Dave(应付组)的本部门应用,
Bob(财务部)能看,Carol(销售部)不能看;反过来 Bob 的本部门应用,Dave 看不到。

## 场景

### 1. 管理员发初始密码

管理员登录控制台 → “人员”页,给 Dave、Bob、Carol 各生成初始密码,记下来“转交”给自己。

- 预期:每个人显示“初始密码,还没改”;审计日志里有三条“生成初始密码”。

### 2. Dave 第一次登录、领令牌、配 agent

在 Dave 的浏览器窗口打开 http://127.0.0.1:8080/console/tokens ,用初始密码登录,按要求改密码,
生成令牌,按上面“准备”里的方法在 `~/ferry-trial/dave` 配好 MCP。员工能看的资料只有 [agent-onboarding.md](agent-onboarding.md)。

- 预期:改完密码直接进入令牌页;`claude mcp list` 显示 ferry 已连接。

### 3. Dave 不经指导做一个应用并发布

在 `~/ferry-trial/dave` 里启动 `claude`,只说需求,例如:

> 帮我做一个报销登记的小应用,能填报销人、金额、事由和日期,本部门的同事都能看到。做好后发布。

agent 问应用名、谁能看到时照实回答。中途不给技术提示。

- 预期:agent 用模板做出应用,发布前请你确认,发布成功后给出 `http://<应用名>.apps.localhost`。
- 记录:用了多久、发布失败了几次、agent 有没有卡住要你帮忙。

### 4. 同事访问

- Dave 自己打开应用地址:直接能用。
- Bob 的窗口打开同一个地址:先跳到 Ferry 登录,登录(第一次要改密码)后回到应用,能用,页面上显示是 Bob。
- Carol 的窗口打开:登录后被拒绝。
- 一个没登录过的无痕窗口打开:跳到 Ferry 登录页。

### 5. Dave 改需求、再发布

> 给报销登记加一个“状态”字段(待审核、已通过、已驳回),列表里能按状态筛选。改好后发布。

- 预期:新版本上线,之前填的数据还在(数据库迁移)。

可选:试一个需要第三方密钥的功能,看 agent 会不会写死密钥、会不会让你去控制台填。

> 每次新增报销后,发一条消息到我们群的钉钉机器人。

- 预期:agent 不把 webhook 写进代码,而是从环境变量读,告诉你到控制台的应用详情“密钥”里填(随便填一个值即可,
  通知发不出去不影响应用);填好后再发布一次。

### 6. 回滚和下线

> 把报销登记回到上一个版本。

> 把报销登记下线。

- 预期:回滚后线上是上一个版本(数据库不回滚,agent 会提醒);下线后地址打不开,控制台显示“已下线”;
  再让 agent 发布一次就恢复,数据还在。

### 7. Bob 做一个全公司可见的页面

Bob 按场景 2 领令牌、在 `~/ferry-trial/bob` 配 agent,然后:

> 帮我做一个团队介绍页,列出财务部的几个人和联系方式,全公司都能看。做好后发布。

- 预期:agent 选静态网页模板;Carol 登录后能打开。

### 8. 管理员停用、恢复、查记录

- 在“管理全部应用”里停用 Dave 的报销登记,填原因。预期:Bob 和 Dave 访问都被拒绝;终端里有发给 Dave 的停用通知;
  Dave 让 agent 发布时被告知应用已停用。
- 恢复。预期:几秒后能访问。
- “审计日志”页:能看到上面所有操作和操作人;点人名、应用名能筛选。
- “人员”页给 Carol 重置密码。预期:Carol 已登录的窗口刷新后要重新登录,用新的初始密码登录后要改密码。

### 9. 收尾

- 把下面的记录表填完,标出要在真正试用前修的问题。
- 测试用的应用可以留着,也可以由 Dave、Bob 让 agent 下线后,管理员在“管理全部应用”里删除。

## 记录(2026-11-22 第一次模拟)

**怎么跑的**:管理员的操作在浏览器里点(控制台“人员”“管理全部应用”“审计日志”页);员工的网页操作(首次登录改密码、领令牌、
访问应用)用 curl 按浏览器的流程走,每人一个 cookie,免得把管理员挤下线(这些页面之前已在浏览器里验证过)。
**员工的 agent 用的是 Antigravity(`agy` 命令行,Gemini 3.8 Flash 模型)**,不是 Claude Code(当时 Claude Code 撞到了每周用量上限),
正好也检验了非 Claude 的 MCP 客户端(P6)。无交互运行时没人回答确认问题,所以需求里直接写了应用名和“直接发布,不用再问我”。
Antigravity 无交互运行要先放行它用到的命令和 Ferry 的工具;有三次停在没放行的命令上,放行后回一句“继续”接着做,不算 agent 卡住。

| 场景 | 结果 | 用时 | 发现的问题 | 备注 |
|---|---|---|---|---|
| 1. 发初始密码 | 通过 | — | 人员页刚打开时一闪“暂无数据” | 三条“生成初始密码”审计记录 |
| 2. 首次登录、配 agent | 通过 | — | — | `agy mcp add --header "Authorization: Bearer …" ferry <地址>/mcp` 可用 |
| 3. 不经指导发布 | 通过 | 约 10 分钟(写代码约 3 分钟,构建上线约 1 分钟) | 应用里显示的部门是 `dingtalk:finance-ap` 这样的 ID | 读了 Ferry 的说明、选对模板、发布前本地类型检查,一次上线 |
| 4. 同事访问 | 通过 | — | — | Dave、Bob 200;Carol 403“你没有权限访问这个应用”;未登录跳登录 |
| 5. 改需求再发布 | 通过 | 约 6.5 分钟 | agent 最后的回复停在“构建中”,没说已上线(Antigravity 的问题) | 自己加了迁移 002,旧数据还在 |
| 5. (可选)第三方密钥 | 部分 | 约 5 分钟 | **agent 让用户去 `http://apps.localhost/console/...` 填密钥,地址是错的** | 没写死 webhook,从 `DINGTALK_WEBHOOK` 读、没配置时跳过;填好后重新发布,应用读到了 |
| 6. 回滚和下线 | 通过 | 回滚约 1 分钟 | — | 回滚提醒数据库不回滚;下线后 404、提醒可能被删除;重新发布后数据还在 |
| 7. 全公司可见页面 | 通过 | 约 8 分钟 | — | 自己选了静态模板;Carol 能打开 |
| 8. 停用、恢复、记录 | 通过 | 恢复后约 11 秒可访问 | 恢复要等十几秒,期间页面没有“处理中”提示,列表还显示“已停用” | 停用后 403、发布被拒、终端有带原因的通知;审计日志完整;重置 Carol 后旧会话失效 |

**验收标准**:试用员工不经指导完成发布 ✅(两个应用、7 次发布全部成功,没有一次失败);同事登录后能访问 ✅;管理员能停用任意应用 ✅。

**试用前要修的**:
1. 给 agent 的使用说明里只写了“Ferry 地址加 /console/…”,agent 不知道 Ferry 的地址,猜错了。**已修复**:说明和密钥扫描的提示里都给出控制台的完整地址。
2. 管理员恢复(停用)应用时没有进度提示,要十几秒才变状态。**已修复**:按钮显示加载中,状态显示“正在停用…”/“正在恢复…”,恢复时提示大约十几秒;已在浏览器里对 finance-team 停用、恢复各一次确认。

**可以顺手改的**:
3. 网关只把部门 ID 传给应用,应用显示 `dingtalk:finance-ap`。**已修复**:网关另外传部门名称(`X-Ferry-User-Department-Names`),模板和给 agent 的说明都用上了。
4. 人员页加载时一闪“暂无数据”。**已修复**(人员、管理全部应用、审计日志、我的应用几个列表都改了)。
5. agent 接入说明([agent-onboarding.md](agent-onboarding.md))只写了 Claude Code。**已修复**:接入说明和令牌页都加了 Antigravity 的命令。

**以后补测**:Claude Code 的用量恢复后,用 Claude Code 再盲测一遍场景 3、5、7。
